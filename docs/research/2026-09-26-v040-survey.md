# 竞品与趋势调研 — oncall-agent v0.4.0 立项依据（2026-09-26）

> 两路并行调研：①GitHub 开源 oncall/AI-SRE 项目；②2025-2026 商业 AI oncall 产品趋势。
> 本文档是 v0.4.0 立项的调研依据存档；决策落点见 `docs/ROADMAP.md` 与 `docs/adr/`。

## 综合结论

- 行业形成六层自主性阶梯：L0 告警接入富化 → L1 降噪收敛 → L2 上下文富化诊断 → L3 交互式 RCA → L4 建议修复(人审) → L5 全自动+postmortem。**安全共识：只读诊断可全自动，执行必须人审（graduated trust）**。本项目 v0.3 的"只读白名单 + 告警不确认不静默"正踩在共识线上。
- 所有活跃项目的共同入口形态是 **Alertmanager webhook 告警接入**；共同出口是诊断结果回投 IM/工单。
- 富化源边际价值排序（对单指标+单知识库项目）：**变更/部署事件 > runbook 命中 > 历史相似事件 > 拓扑**。
- **Eval 驱动是 2025-2026 最一致的行业教训**（Datadog 为 Bits AI SRE 单建 eval 平台、incident.io 每日用历史事件回测、SREGym 直接做成带 oracle 的基准）。
- MCP 已成可观测性事实接口协议（Grafana 官方 Go MCP server ~3.5k★ 可直接抄，含 `--disable-write` 式安全开关）。
- 教训/禁区：grafana/oncall（排班通知赛道）2026-03 归档；keptn、Tencent/Metis 等纯 ML AIOps 一代集体退场——价值上移到 agent 层，**不要做收敛平台/排班/自动修复**。

### v0.4.0 候选能力（两路调研信号强度合并排序）

1. `POST /alert`（Alertmanager webhook 兼容）+ 告警驱动诊断 → 结构化诊断报告【开源路排1】
2. 诊断 eval 基线（fixture 告警 → 引用命中/明示无匹配断言 → 回归门禁）【两路都排前二】
3. MCP server 对外暴露（time_now/rag_search/prometheus_query 挂出去）【两路都提】
4. `deploy_events` 变更富化（第四只读白名单工具）【商业路排2，行业验证的最高价值 RCA 信号】
5. 知识回流飞轮（确认有效的诊断报告入库 Qdrant，带 incident 标签）【两路都提】
6. 上下文预算护栏（工具输出 token/条数预算+截断标记）【开源路】
7. anonymize 脱敏（送 LLM 前可逆掩码）【开源路】
8. 通知写回（诊断完成 POST Slack/飞书 webhook——"通知"不是 remediation，边界需 ADR）【开源路】

### 两路一致不建议 v0.4 碰

自动修复/remediation（违背只读定位，行业也要到 L4 且人审）、告警 dedup/correlate 平台（Keep 的重资产领域）、oncall 排班升级（grafana/oncall 归档已证明）、多 agent 协作（单人项目复杂度不划算）、拓扑/CMDB（无数据源）。

## 报告一：开源 Oncall / AI-SRE 项目调研

### 1. k8sgpt-ai/k8sgpt — Go，8.2k stars，CNCF Sandbox，活跃

- **核心能力**：不是自由 agent，而是"确定性 analyzer 扫描 + LLM 解释"。内置 14 个默认 analyzer + 15 个可选，把 SRE 经验固化为代码规则，扫描出故障后交给 LLM 生成解释和修复建议。产出是文字建议，**不执行任何修复**。
- **架构**：CLI + `serve` 模式（gRPC）+ operator（集群内持续扫描，可对接 Prometheus/Alertmanager）+ **MCP server**（`serve --mcp`，12 个 tools，stdio/HTTP 双模式）。LLM 调用是单次 explain，非 ReAct 循环。
- **动作边界**：纯只读。安全护栏特色是 **anonymize**：发送给 LLM 前对 K8s 对象名、label 做掩码替换（返回时反解），建议生产用本地模型。
- **知识沉淀**：无 RAG；知识"沉淀"在 analyzer 代码里。
- **参照价值**：同为 Go；"规则先定位、LLM 后解释"分工；anonymize；MCP server 对外。

### 2. HolmesGPT — Python，3.4k stars，已进 CNCF Sandbox，非常活跃

- **核心能力**：最典型的 SRE 诊断 agent。agentic loop 查询多源观测数据做 RCA；双向告警集成（从 AlertManager/PagerDuty/OpsGenie/Jira 拉取告警调查后把结论写回源系统）；**Operator 模式**：后台 7x24 健康检查，主动发现问题推 Slack，可开 PR 修复。
- **架构**：单 agent 循环 + **toolset 插件体系**（40+ 内置：Prometheus、Grafana/Loki/Tempo、Datadog、K8s、Docker、ES、Kafka、SQL、AWS/Azure/GCP、ArgoCD、Confluence runbook 等，全部 MCP 化中）+ 自定义 toolset（任意 REST API 声明成工具）。
- **动作边界**：README 明言 "**By design, HolmesGPT has read-only access** and respects RBAC"，写操作通过独立的 "Kubernetes Remediation (MCP)" toolset **显式选装**。上下文护栏是工程亮点：服务端过滤、output transformer 把大 payload 挡在 context window 外；每工具内存上限、大结果流式落盘。
- **参照价值最高**：40+ toolset 的插件抽象、只读 by design + 选装 remediation、输出预算管理、告警写回闭环。

### 3. keephq/keep — Python，12.4k stars，2025-05 被 Elastic 收购

- **核心能力**：开源 AIOps 告警管理平台。聚合 110+ provider 告警；去重、富化、过滤、**关联成 incident**；YAML workflow 引擎（"监控界的 GitHub Actions"）；AI 做摘要、时间线还原、噪声削减、postmortem 草稿。
- **架构**：平台型（FastAPI + React），provider 抽象统一接入；不是诊断 agent。
- **参照价值**：Alertmanager webhook payload 作为通用告警事实标准；dedup/enrich/correlate 流水线概念；但平台范围对单人 Go 项目太大。

### 4. robusta-dev/robusta — Python，3.1k stars，活跃

- **核心能力**："Robusta Classic" = 规则式 Prometheus 告警富化引擎：智能分组降噪、告警附带 pod 日志/图表、无需 PromQL 的问题检测、**K8s 变更追踪**（把告警和 rollout 关联）、auto-resolve、self-healing playbook。AI RCA 全部交给 HolmesGPT。
- **参照价值**：**change tracking 关联告警与变更是 RCA 的杀手锏**；"规则做快路径、agent 做慢诊断"的分层。

### 5. grafana/oncall — Python，3.9k stars，**已归档**

- 2025-03-11 进维护模式，**2026-03-24 正式归档**，官方引导迁往闭源 Grafana Cloud IRM。传统 oncall 基础设施（值班表/升级/通知），完全没有 AI 诊断。
- **教训**：oncall 排班/通知是重运营、商业化挤压严重的赛道；开源 AI 诊断项目应避开，专注诊断闭环。

### 6. VersusControl/versus-incident — **Go**，780 stars，活跃 — 技术栈最接近的对标

- **核心能力**：自托管 AI SRE。两条进告警的路：① AI agent 学日志（Drain 式模式挖掘建"正常模式目录"，只对从未见过的新错误开 incident）；② webhook 收告警（Alertmanager/Grafana/Sentry/CloudWatch SNS → `POST /api/incidents`）。AI 对每条 incident 产出 summary/severity/suggested next steps 后多通道分发。
- **架构**：Go HTTP 网关 + agent goroutine + Redis；Go template 自定义告警消息；非 ReAct。
- **护栏最值得抄**：**training → shadow → detect 三段式灰度**——training 只学不报，shadow 记录 "would have alerted"，验证判断力后才真发 incident；日志送 AI 前正则脱敏；regex 预过滤挡噪音。
- **参照价值**：同为 Go + webhook + 告警模板分发，工程形态可直接对照；shadow mode 是"只读系统建立信任"的范本。

### 开源路 v0.4 建议（按杠杆排序，均不破只读闭环）

1. **`POST /alert`（Alertmanager webhook 兼容）+ 告警驱动诊断**：收告警自动触发既有 Plan-Execute，输出结构化诊断报告（severity/引用片段/runbook 链接/建议下一步）。投入最小、闭环增益最大。
2. **诊断质量可度量**：扩展 `cmd/evalbaseline`，借鉴 SREGym diagnosis-stage oracle——引用命中 expect_doc 即得分，report 出"告警→诊断→引用命中"基线分。
3. **上下文工程护栏**：工具输出加 token/条数预算与截断标记（HolmesGPT output budgeting）。
4. **历史事件回流**：人工确认过的诊断结论入库 Qdrant 作"历史相似事件"辅助证据。纯写自有库，仍是只读系统。
5. **匿名化/脱敏**：送 LLM 前对主机名/IP/secret 可逆掩码（k8sgpt anonymize）。
6. **对外 MCP server**：把三只读经 ADR-0004 传输缝反向暴露（对标 k8sgpt serve --mcp）。
7. **通知写回（可选）**：诊断完成 POST Slack/飞书 webhook——是"通知"不是 remediation，建议补 ADR 说明边界。

## 报告二：2025-2026 商业 AI Oncall 产品趋势

### 一、自主性六层阶梯

| 层级 | 能力 | 代表事实 |
|---|---|---|
| L0 告警接入与富化 | 事件接入、去重、归一化、附加上下文 | PagerDuty Event Orchestration；BigPanda pipeline "filters, normalizes, enriches" |
| L1 告警降噪/收敛 | ML 聚类成 incident | BigPanda 宣称 98% 噪声削减；PagerDuty AIOps 91%；Keep "1000s into 10s" |
| L2 上下文富化诊断 | 自动拉 runbook/遥测/变更历史分诊 | incident.io "Investigations"："no more cold starts" |
| L3 交互式诊断/RCA | agent 多步调查、证据链+置信度 | Resolve.ai：<5 分钟出 RCA；Cleric 假设驱动，Gartner Cool Vendor 2025 |
| L4 建议修复/带审批执行 | 修复 PR 或 runbook，人批后执行 | Cleric："Read access by default, write access when you're ready"；incident.io"唯一系统变更是人 review 的 PR" |
| L5 全自动修复+复盘 | 低风险自动执行、自动 postmortem | Datadog Bits AI SRE（2025-12 GA）宣称 MTTR 降 ~70%；Rootly AI postmortem 初稿 |

新方向：Cleric 把"部署变更验证"做成独立模式；Traversal 打 "ambient AI SRE" 7×24 巡检。资本热度极高：Resolve.ai Series A 估值 $1B；SRE.ai 获 Salesforce Ventures 领投。

### 二、行业共识的安全边界

**诊断层可全自动（只读），执行层必须人审，"分级信任"是标准架构。**

- 只读诊断层已敢全自动：Bits AI SRE 自动调查、Cleric "接走 pager"、Resolve.ai "investigates 100% of alerts"。默认只读是准入门槛（Resolve.ai/Cleric 明示 read-only by default；Grafana MCP server 有 `--disable-write`/`--enabled-tools` 白名单开关）。
- 执行层成熟度阶梯：diagnosis-only → remediation with approval → autonomous resolution with verification。到 2026 年 HITL 仍是现实部署主流（Komodor 判断），全自动只限"已知模式自愈"。
- 五条硬护栏已成产品标配：动作白名单、爆炸半径限制、人工审批门、不可篡改审计日志、kill switch——与本项目"只读白名单，白名单外一律拒绝"同构。

### 三、上下文富化数据源（边际价值排序）

**变更/部署事件 > runbook 命中 > 历史相似事件 > 拓扑**。变更事件 2025 年被提到最高优先级（Cleric 三大模式之一、Rootly change-aware RCA、Resolve 独立上下文源）——行业统计上变更是最常见根因。遥测三件套 metrics/logs/traces 是基础；Slack 会话、代码/PR、云资源、工单是扩展。

### 四、知识沉淀与反馈闭环

- Postmortem 模板化+AI 初稿成标配（Rootly/PagerDuty Copilot/Resolve.ai）。
- 每次事件反哺：incident.io Nexus "learns from each incident" + 每日历史事件自动回测（backtesting）；Cleric "compounds over time"。
- 工程师反馈回流（approve/request-changes、误报关闭）作为召回/训练信号。
- 知识机器可执行化流派（Shoreline.io，已被 NVIDIA 收购）：runbook 不只给人读，还是 agent 可调用工具——启示：给知识加结构化"检查步骤"元数据，rag_search 命中可直接变 agent 诊断步骤。

### 五、2025-2026 趋势

1. **MCP 成可观测性事实接口协议**：Grafana 官方 Go mcp-grafana（~3.5k★，含 `--disable-write`）；Datadog/New Relic/Sentry/Rootly/incident.io 全面跟进。
2. Agent 自主性上探到"自主调查"，以 graduated trust 约束。
3. 多 agent 分工（Datadog 多领域 agent、LogicMonitor Edwin AI 10+ agent、incident.io 对抗性 agent 压测结论）。
4. **Eval 驱动成竞争壁垒**（Datadog 为 Bits AI SRE 单建 eval 平台；incident.io 每日回测）。
5. 并购整合加速（Elastic 收 Keep、NVIDIA 收 Shoreline、Moogsoft 归 Dell）——独立 AIOps 层被平台吞并，价值上移到 agent 层。

### 商业路 v0.4 建议（排序）

1. **Eval 驱动的诊断质量基线**（行业最一致教训 + 你有 `cmd/evalbaseline` 现成地基）。
2. **`deploy_events` 变更富化**（第四只读白名单工具，GitHub API 只读拉最近 deploy/commit，告警时间窗 × 最近变更并成上下文）。
3. **MCP server 化**（把三只读暴露为 MCP tools，借 MCP 生态分发，白名单语义原样保留）。
4. **知识回流飞轮**（确认有效的报告入库 Qdrant 带 incident 标签 + 反馈打标）。
5. 轻量告警收敛（可选/延后——需告警量才有意义）。

明确不建议：自动修复/执行类、多 agent 协作、拓扑/CMDB。
